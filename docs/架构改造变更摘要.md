# 架构改造变更摘要：API 前缀统一迁移（方案 1）

> 变更类型：架构一致性重构（Breaking Change，仅影响接口路径）
> 变更日期：2026-11-10
> 影响范围：后端路由 / 前端调用 / 后端测试 / ESP32 固件 / 模拟器 / 文档

---

## 一、变更背景

平台在迭代中出现了两套接口前缀并存的问题：

- 迁移较早的模块已统一到 `/api/v1/*`（auth、orders、payments、settlements、twin、iot）；
- 其余 7 个模块仍停留在 `/api/*`（users、resources、reviews、stats、match、audit-logs、devices）。

由此产生三类实际故障：

1. **测试大面积失败**：`test_reviews_devices_iot.py`、`test_auth.py`、`test_stats.py` 等已按 `/api/v1/*` 编写，而后端路由仍是旧前缀，累计 47 项用例预存在失败。
2. **前端真实失效**：`orders.ts`、`iot.ts` 仍在请求 `/api/orders`、`/api/iot/*`，后端早已是 v1，线上请求 404。
3. **令牌续期失效**：`client.ts` 的 refresh 请求指向 `/api/auth/refresh`，服务端实际为 `/api/v1/auth/refresh`。

本次按「方案 1」补齐迁移：**全部业务路由统一到 `/api/v1/*`，仅健康检查保留根路径**。

---

## 二、变更内容

### 2.1 后端路由（7 个模块）

| 文件 | 变更前 | 变更后 |
|---|---|---|
| `backend/app/routers/users.py` | `/api/users` | `/api/v1/users` |
| `backend/app/routers/resources.py` | `/api/resources` | `/api/v1/resources` |
| `backend/app/routers/reviews.py` | `/api/reviews` | `/api/v1/reviews` |
| `backend/app/routers/stats.py` | `/api/stats` | `/api/v1/stats` |
| `backend/app/routers/match.py` | `/api/match` | `/api/v1/match` |
| `backend/app/routers/audit.py` | `/api/audit-logs` | `/api/v1/audit-logs` |
| `backend/app/routers/devices.py` | `/api/devices` | `/api/v1/devices` |

说明：

- `devices` 一并迁移。依据是设备相关测试早已按 `/api/v1/devices` 编写，若只迁 6 个模块，该测试文件仍无法通过。
- **不变更**：`/api/health`（健康检查保持根路径，符合运维惯例，也被监控脚本、`Header.vue` 与部署文档直接引用）。
- **不变更**：`auth` / `orders` / `payments` / `settlements` / `twin` / `iot` 六个路由原本已是 `/api/v1/*`。
- 无数据库结构变更，无 Alembic 迁移，无配置项变更。

### 2.2 前端调用（10 个文件）

`frontend-vue/src/api/` 下：

- 随路由迁移同步：`users.ts`、`resources.ts`、`reviews.ts`、`stats.ts`、`match.ts`、`audit.ts`、`devices.ts`（含 `/auto-bind`、`/telemetry`、`/import`、`/ota` 等子路径）。
- 修复既有失效：`orders.ts`（`/api/orders` → `/api/v1/orders`）、`iot.ts`（`/api/iot/*` → `/api/v1/iot/*`）。
- 修复令牌续期：`client.ts` 的 refresh 地址改为 `/api/v1/auth/refresh`。

未改动：`auth.ts`、`twin.ts`（原本已是 v1）、`ws/realtime.ts`（`/ws/realtime`，不属于 `/api`）、`demand-app`（已全部 v1）。

### 2.3 后端测试（5 个文件）

`conftest.py`、`test_matching.py`、`test_resources_orders.py`、`test_security.py`、`test_devices_ota.py` 中的请求路径统一加 `v1`。

`test_auth.py`、`test_stats.py`、`test_reviews_devices_iot.py`、`test_payments_settlements.py`、`test_trade_hardening.py` 原本已是 v1，未改动。

### 2.4 固件与模拟器

- `iot/firmware/ota.py`：清单、文件下载、回执三处 URL 与模块 docstring 全部改为 `/api/v1/devices/ota/*`。
- `iot/firmware/releases/3.1.0/`：执行 `python iot/tools/make_release.py 3.1.0` 重新生成发布包，`manifest.json` 中的 `sha256` 随之更新。
- `iot/simulator.py`：OTA 回执地址改为 `/api/v1/devices/ota/report`。
- `iot/firmware/README.md`：OTA 流程与验证命令路径同步。
- `iot/firmware/main.py` 与 `simulator_http.py` 原本就是 v1，未改动。

### 2.5 文档

- `docs/详细设计.md`：5.1~5.7 接口表全部路径（认证/用户/资源/订单/撮合/IoT 与设备/评价/统计/审计），以及正文中引用的 refresh、遥测示例。
- `docs/部署运维说明.md`：验证命令、故障排查中引用的接口路径。
- 两处文档中的 `/api/health` 保持不动。

## 三、兼容性影响

| 对象 | 影响 |
|---|---|
| 前端 Web 应用 | 已同步，无需额外操作 |
| 已部署 ESP32 节点 | **必须重新 OTA 或重刷固件**，否则 OTA 拉包/回执会打到旧路径并 404 |
| Python 模拟器 | 已同步，重新拉取代码即可 |
| nginx / Docker Compose | 无需改动。`location /api/` 为前缀透传，`/api/v1/*` 天然命中 |
| 外部调用方 / 旧脚本 | **Breaking**：`/api/resources`、`/api/devices` 等旧路径返回 404，需改为 `/api/v1/*` |
| `/api/health` | 不变，监控与探活无需调整 |

灰度建议：若已有在线节点暂不便升级，可临时在 nginx 增加旧前缀 rewrite 到 `/api/v1/` 作为过渡，待节点全部 OTA 完成后移除。

| 验证项 | 命令 | 结果 |
|---|---|---|
| 后端全量回归 | `pytest -q`（独立库 `hhlg_mig_check`） | **114 项全部通过**，原 47 项预存在失败清零 |

| 前端单测 | `npm run test` | 10 项通过 |
| 前端构建 | `npm run build` | 通过（含 `vue-tsc` 类型检查，仅有既存 chunk 体积提示） |
| 前缀残留检查 | 全仓检索旧前缀 | 除 `/api/health` 与前端模块别名 `@/api/*` 外无残留，无 `api/v1/v1` 重复 |

## 五、后续事项

- 实机验证（待硬件到货）：GW-01 跑通一次完整 OTA（建任务 → MQTT 下行 → 拉取 → 校验 → 重启 → 回执）；ESP-NOW 汇聚联调。
- 建议在 CI 中增加一条静态检查：禁止新增 `/api/`（非 `v1`、非 `health`）路径，防止前缀再次分裂。
- 建议把 `devices` 与 `iot` 的职责边界在详细设计中补充说明：`/api/v1/iot/*` 面向设备侧上报，`/api/v1/devices/*` 面向管理侧运维。
