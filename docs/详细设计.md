# 详细设计

> 怀化国际陆港物流资源共享与智能撮合平台
> 本文档与当前代码实现保持一致（含 IoT、评价、鉴权、3D 孪生与部署方案）。

---

## 一、系统总体架构

```
┌──────────────────────────────────────────────────────┐
│ 展示层  Vue3 + TypeScript + Three.js(数字孪生) + ECharts │
│        数字孪生大屏 / 运营管理（资源·市场·订单）           │
├──────────────────────────────────────────────────────┤
│ 应用层  FastAPI 单体服务                                │
│        认证 / 资源 / 订单 / 撮合 / IoT / 设备 / 评价      │
├──────────────────────────────────────────────────────┤
│ 数据层  MySQL 8（业务数据） + Redis 7（缓存与实时值）      │
├──────────────────────────────────────────────────────┤
│ 接入层  EMQX 5（MQTT） ← ESP32 传感器 / Python 模拟器     │
└──────────────────────────────────────────────────────┘
```

**主数据流**：
传感器采集 → MQTT(`iot/{device_code}/data`) → FastAPI 订阅入库 → Redis 最新值(TTL 5s) → WebSocket 广播 → 大屏/孪生实时刷新。

## 六、核心业务规则

### 6.1 撮合评分

对 `status = available` 的资源打分排序，总分与分项一并返回：

| 维度 | 上限 | 计算方式 |
|---|---|---|
| 价格得分 | 30 | 候选集内最低价得满分，最高价得 0，线性递减 |
| 信用得分 | 20 | `20 × clamp((credit - 60) / 40, 0, 1)` |
| 时间窗口 | 20 | 覆盖天数 × 2，上限 20 |
| 类型匹配 | 10 | 指定 resource_type 且命中 +10 |

结果缓存 30 秒（键 `hlg:match:recommend:*`）。

### 6.2 订单状态机与资源联动

```
pending ──确认──► confirmed ──开始──► ongoing ──完成──► finished
   │                  │
   └──────取消────────┴──────────► cancelled
```

- 创建订单：资源 `available → booked`，并锁定当时佣金率
- 订单转 `finished`：写入 `commission = total_price × commission_rate`
- 订单转 `cancelled/finished`：若该资源无其他活跃订单，`booked → available`
- 每次状态变更推送 `resource_updated`，驱动大屏冷链箱颜色刷新

### 6.3 信用分重算

评价提交后按被评价人收到的**全部评价**确定性重算，避免增量漂移：

```
无评价      → 100
有评价      → clamp(round(60 + 40 × (平均分 - 1) / 4), 0, 100)
```

即 5 星 = 100 分，1 星 = 60 分，4 星 = 90 分。

### 6.4 预警规则

- 阈值按「资源级规则 → 全局规则 → 系统配置（`ALERT_TEMP_MIN/MAX`、`ALERT_HUMIDITY_MAX`）」顺序生效
- 温度低于下限或高于上限 → `critical`；湿度高于上限 → `warn`
- 规则可在「告警处理 → 告警规则」页维护，支持按资源覆盖、停用与恢复默认
- 同设备同类型告警 10 分钟内只记一条
- 运营人员标记已解决后状态置为 `resolved`，并推送 `alert_resolved`，大屏活跃告警即时移除

### 6.5 资源审核流程

```
发布 → pending ──管理员通过──► available ──属主下架──► offline
            └──管理员驳回──► offline ──属主修改后重新提交──► pending
```

- 新发布资源固定为 `pending`，市场不可见、不可下单
- 属主不能自行把 `pending` 改成 `available`（返回 403），必须由管理员审核
- 只有 `pending` 资源可审核；重复审核返回 400

### 6.6 设备离线检测

- 后台协程每 30 秒扫描一次在线设备
- 最近一条遥测早于 `DEVICE_OFFLINE_SECONDS`（默认 90 秒）或从未上报 → 置为 `offline`
- 设备再次上报数据时自动恢复 `online`

### 6.7 安全与账号

**登录失败限流**：

- 同一用户名连续失败超过 `LOGIN_MAX_ATTEMPTS`（默认 5）次后锁定 `LOGIN_LOCK_SECONDS`（默认 900 秒）
- 锁定期间返回 429；Redis 不可用时自动降级为不限流，不阻断正常登录
- 登录成功即清除失败计数

**令牌与无感续期**：

- 登录返回 `access_token`（默认 24 小时）+ `refresh_token`（默认 7 天）
- 前端请求遇 401 时自动用 refresh token 换取新 token 对并重试原请求；并发 401 合并为单次刷新
- 刷新令牌仅能用于 `/api/auth/refresh`，不可当作 access token 使用（通过 `type` 声明区分）

**修改密码**：

- 需提供旧密码校验；新密码 ≥8 位且含字母与数字；新旧不能相同
- 修改后旧密码立即失效

**审计日志**：

- 登录成功、修改密码、资源审核、用户角色/启用变更、告警处理均写入 `audit_logs`
- 记录操作人、动作、目标对象、变更描述与来源 IP
- 仅管理员可查询，支持按动作/用户名筛选与分页

## 七、实时推送设计

### 7.1 事件类型

| type | 触发时机 | 前端动作 |
|---|---|---|
| `hello` | WS 建立连接 | 忽略 |
| `iot_data` | 收到 MQTT 数据 | 更新设备最新值与趋势曲线 |
| `order_created` | 新建订单 | 刷新订单列表 |
| `order_status_changed` | 订单状态变更 | 局部更新订单状态 |
| `resource_updated` | 资源状态变化 | 刷新资源列表，驱动 3D 配色 |
| `alert_resolved` | 告警被标记已处理 | 从大屏活跃告警中移除 |

### 7.2 跨线程广播

MQTT 订阅线程与 HTTP 线程都会发布事件，`BroadcastHub` 通过线程 ID 判断：
主线程用 `ensure_future`，其他线程用 `run_coroutine_threadsafe` 投递到主事件循环。

> 因广播与订阅均在进程内，后端必须**单进程**运行（`--workers 1`），否则 WS 客户端收不到其他进程产生的事件。

#### 8.1.1 替换为真实模型

现有 5 个 GLB 为程序化生成的占位资产，接口层不区分来源，按下面的约束替换文件即可，**无需改代码**：

| 约束 | 要求 |
|---|---|
| 文件路径 | `frontend-vue/public/models/<name>.glb`，文件名保持不变 |

1. Blender 导出 glTF 2.0（`.glb`，勾选「应用修改器」「+Y 向上」）

## 九、安全设计

| 项 | 方案 |
|---|---|
| 密码存储 | PBKDF2-HMAC-SHA256，10 万次迭代，随机盐 |
| 密码强度 | 注册时校验 ≥8 位且同时含字母与数字 |
| 令牌 | JWT HS256，默认 24 小时，密钥来自环境变量且强制必填 |
| 权限模型 | 三角色 supplier / demander / admin + `require_admin` 依赖 |
| 账号状态 | `is_active` 为假时所有接口返回 403 |
| 提权防护 | admin 角色不开放自助注册；管理员不能禁用/降级自己 |
| 设备接入 | HTTP 上报需 `X-Device-Token`；MQTT 走 Broker 侧认证 |
| 实时通道 | WS 允许匿名只读（大屏），携带无效 token 则拒绝握手 |
| CORS | 白名单来自 `CORS_ORIGINS`，不再全开 |
| 密钥管理 | `.env` 不入库（`.gitignore`），模板见 `.env.example` |

## 十二、设备接入设计

- **硬件方案**：ESP32 + DHT22（温湿度）+ GPS，MicroPython 定时采集
- **上报协议**：MQTT 主题 `iot/{device_code}/data`，JSON 载荷
- **备选协议**：HTTP `POST /api/iot/data`，需设备令牌
- **绑定关系**：设备通过 `resource_id` 关联资源，一个资源可挂多台设备
- **离线判定**：以最近一次 `recorded_at` 为准（后续可加心跳超时任务）
- **模拟器**：`iot/simulator.py` 每 3 秒为 4 台虚拟设备生成温湿度与坐标，支持 `MQTT_HOST` / `MQTT_PORT` / `PUBLISH_INTERVAL` 环境变量
