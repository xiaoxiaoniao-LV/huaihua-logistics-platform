# 部署与运维说明

怀化国际陆港物流资源共享与智能撮合平台 —— 生产部署、日常运维与故障排查手册。

## 一、系统概览

### 1.1 服务拓扑

```
                     ┌──────────────┐
   浏览器  ────────► │  frontend    │  Nginx 1.27（静态站点 + 反向代理）
                     │   :80        │
                     └──────┬───────┘
                /api/*      │      /ws/*（Upgrade）
                            ▼
                     ┌──────────────┐        ┌──────────────┐
                     │  backend     │◄──────►│    mysql     │
                     │  FastAPI     │        │  MySQL 8.0   │
                     │  :8000       │        └──────────────┘
                     │  单进程       │◄──────►┌──────────────┐
                     │              │        │    redis     │
                     └──────┬───────┘        │  Redis 7     │
                            │ MQTT 订阅       └──────────────┘
                            ▼
                     ┌──────────────┐◄────── ┌──────────────┐
                     │    emqx      │        │  simulator   │（可选，仅演示）
                     │  EMQX 5.7    │        │  模拟传感器   │
                     └──────────────┘        └──────────────┘
```

### 1.2 容器与端口

| 服务 | 容器名 | 内部端口 | 宿主机端口（可配） | 说明 |
|---|---|---|---|---|
| frontend | hhlg-frontend | 80 | `${HHLG_WEB_PORT:-8080}` | 对外唯一入口 |
| backend | hhlg-backend | 8000 | `${HHLG_API_PORT:-8010}` | 直连调试用，生产可关闭 |
| mysql | hhlg-mysql | 3306 | `${HHLG_MYSQL_PORT:-3307}` | 数据持久化到命名卷 |
| redis | hhlg-redis | 6379 | 不对外 | 缓存 |
| emqx | hhlg-emqx | 1883 / 18083 | `${HHLG_MQTT_PORT:-1884}` / `${HHLG_EMQX_DASH_PORT:-18084}` | MQTT Broker 与控制台 |
| simulator | hhlg-simulator | — | — | `--profile demo` 才启动 |

> 默认端口已避开常见占用（8000、1883、6379 常被其他项目使用）。如冲突，改根目录 `.env` 即可。

## 三、首次部署

```bash
# 1. 准备环境变量（务必修改密钥）
cp .env.example .env
#    编辑 .env，至少修改 JWT_SECRET、MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、EMQX_DASH_PASSWORD

# 2. 构建并启动全部服务
docker compose up -d --build

# 3. 等待健康检查通过（约 1–2 分钟，MySQL 首次初始化较慢）
docker compose ps

# 4. 验证
curl http://localhost:8080/api/health
# 期望：{"status":"ok","app":"怀化国际陆港物流资源共享与智能撮合平台"}
```

首次启动时后端会自动执行 `alembic upgrade head` 建表，无需手工建库建表。

需要演示用的模拟传感器数据时：

```bash
docker compose --profile demo up -d
```

访问入口：

| 用途 | 地址 |
|---|---|
| 数字孪生大屏 / 运营管理 | http://localhost:8080 |
| API 健康检查 | http://localhost:8080/api/health |
| EMQX 控制台 | http://localhost:18084（用户 `admin`，密码为 `.env` 中 `EMQX_DASH_PASSWORD`） |

## 五、日常运维

### 5.1 启停与状态

```bash
docker compose ps                    # 查看状态（带 healthy 标记）
docker compose up -d                 # 启动
docker compose up -d --build         # 重新构建并启动（代码更新后）
docker compose restart backend       # 只重启某个服务
docker compose stop                  # 停止（容器保留）
docker compose down                  # 停止并删除容器（数据卷保留）
docker compose down -v               # ⚠️ 连数据卷一起删除，MySQL 数据会丢失
```

### 5.2 日志

```bash
docker compose logs -f backend       # 跟踪后端日志
docker compose logs --tail 200 frontend
docker compose logs -f emqx
```

后端关键日志：
- `[mqtt] connected ... subscribing iot/+/data` —— MQTT 订阅成功
- `INFO [alembic.runtime.migration] Running upgrade ...` —— 迁移执行
- `[hub] 投递异常` —— WebSocket 广播异常

### 5.3 健康检查

```bash
curl http://localhost:8080/api/health     # 后端
curl -I http://localhost:8080/            # 前端
docker inspect --format "{{.State.Health.Status}}" hhlg-backend
```

`docker compose ps` 中若出现 `unhealthy`，先看 `docker compose logs <服务>`。

### 5.4 滚动更新

```bash
git pull
docker compose build backend frontend
docker compose up -d backend frontend
```

后端启动时会自动执行未应用的数据库迁移。

## 六、数据库迁移（Alembic）

表结构完全由 Alembic 管理，应用启动**不会**自动建表。

当前迁移链：`0001_initial`（7 张业务表）→ `0002_alert_rules`（告警阈值规则表）→ `0003_audit_logs`（审计日志表）。

```bash
# 查看当前版本
docker compose exec backend alembic current

# 查看迁移历史
docker compose exec backend alembic history

# 应用全部迁移（后端容器启动时也会自动执行）
docker compose exec backend alembic upgrade head

# 回滚一个版本
docker compose exec backend alembic downgrade -1

# 修改模型后生成新迁移（生成后务必人工检查）
docker compose exec backend alembic revision --autogenerate -m "add xxx field"
docker compose exec backend alembic upgrade head
```

注意事项：

- `alembic.ini` 必须保持**纯 ASCII**（Windows 下 Python 以 GBK 读取配置，中文会抛 `UnicodeDecodeError`）
- 迁移脚本位于 `backend/alembic/versions/`，需随代码一起提交
- 已有数据的环境接入 Alembic 时用 `alembic stamp head` 打基线，不要直接 `upgrade`

## 七、设备接入

### 7.1 MQTT 上报（推荐）

| 项 | 值 |
|---|---|
| Broker | `localhost:1884`（容器内为 `emqx:1883`） |
| Topic | `iot/{device_code}/data` |
| Payload | JSON |

```json
{
  "device_code": "CW-01",
  "temperature": -18.5,
  "humidity": 62.3,
  "longitude": 110.42,
  "latitude": 27.55
}
```

后端订阅 `iot/+/data`，收到后：写库 → 更新 Redis 最新值（TTL 5s）→ WebSocket 推送到大屏。

> ESP32 + DHT22 实机固件与接线步骤见 [`iot/firmware/README.md`](../iot/firmware/README.md)：
> 修改 WiFi/服务器地址后上传 `main.py` 即可，MQTT 不通时会自动降级为 HTTP 上报。

### 7.2 HTTP 上报（备选）

```bash
# 令牌值见根目录 .env 的 DEVICE_INGEST_TOKEN；未配置该变量时可省略此请求头
curl -X POST http://localhost:8080/api/iot/data \
  -H "Content-Type: application/json" \
  -H "X-Device-Token: <DEVICE_INGEST_TOKEN>" \
  -d '{"device_code":"CW-05","temperature":-17.2,"humidity":60.1}'
```

配置了 `DEVICE_INGEST_TOKEN` 时，缺失或错误的令牌会返回 401。

### 7.3 设备与资源绑定

设备通过 `resource_id` 关联到资源（冷链箱/仓库），绑定后大屏点击箱体即可看到该设备的温湿度。

```bash
# 登录拿到 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"<账号>","password":"<密码>"}' | grep -o '"access_token":"[^"]*' | cut -d'"' -f4)

# 查看设备
curl http://localhost:8080/api/devices -H "Authorization: Bearer $TOKEN"

# 单台绑定到资源 ID=1
curl -X PUT http://localhost:8080/api/devices/1 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"resource_id":1}'

# 批量：把未绑定设备按序绑定到可用冷链箱
curl -X POST http://localhost:8080/api/devices/auto-bind -H "Authorization: Bearer $TOKEN"
```

### 7.4 告警阈值

当前为固定阈值（`backend/app/routers/iot.py`）：

- 温度 < -30℃ 或 > -5℃ → `critical`
- 湿度 > 90% → `warn`
- 同设备同类型告警 10 分钟内只记一条

## 八、故障排查

### 8.1 镜像拉取慢 / 超时

现象：`docker compose build` 长时间卡在 `Pulling fs layer`。

处理：
- 为 Docker Desktop 配置镜像加速（Settings → Docker Engine 的 `registry-mirrors`）
- 前端 npm 依赖已默认走 `registry.npmmirror.com`，可用 `NPM_REGISTRY` 覆盖
- 可先单独预拉基础镜像：`docker pull python:3.12-slim`、`docker pull node:22-alpine`、`docker pull nginx:1.27-alpine`

### 8.2 构建时报 Debian 源不可达

现象：`backend` 构建失败于 `apt-get update ... 404 / Connection failed`。

原因：当前后端镜像**不依赖 apt**（健康检查使用 Python 标准库）。若你在 Dockerfile 中新增了 `apt-get`，请改为不依赖系统包的方式，或先解决容器出网/代理问题。

### 8.3 `docker` 命令连不上引擎

现象：`failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`。

处理：
- 确认 Docker Desktop 已启动完成（托盘图标为运行状态）
- 若 `desktop-linux` 上下文未就绪，可临时改用默认上下文：`docker --context default ps`

### 8.4 端口被占用

现象：`Bind for 0.0.0.0:xxxx failed: port is already allocated`。

处理：改根目录 `.env` 中对应端口后 `docker compose up -d`：

```ini
HHLG_WEB_PORT=8081
HHLG_API_PORT=8011
HHLG_MQTT_PORT=1885
```

### 8.5 页面能开但接口 404 / 数据为空

排查顺序：

1. `docker compose ps` 看 backend 是否 `healthy`
2. `docker compose logs backend --tail 100` 看是否有异常
3. `curl http://localhost:8080/api/health`
4. 确认 frontend 的 `nginx.conf` 中 `/api/` 指向 `http://backend:8000`

### 8.6 大屏实时数据不动

1. 确认 MQTT 已连接：日志出现 `[mqtt] connected`
2. 确认有数据源：`docker compose --profile demo up -d` 或真实设备在发 `iot/{code}/data`
3. 直接查库：`curl http://localhost:8080/api/iot/data?limit=5`
4. WebSocket 检查：浏览器控制台是否有 `[WS] 已连接`

### 8.7 修改代码后行为没变化

- 后端容器**没有**热重载，需 `docker compose up -d --build backend`
- 前端是构建产物，需重建镜像
- 开发模式（`uvicorn --reload` + `vite`）才有热更新

### 8.8 PowerShell 里中文显示成乱码

现象：`Invoke-RestMethod` 输出 `å·é¾ç®±ä½`。

原因：Windows PowerShell 5.1 把 UTF-8 响应按 Latin-1 解码，**只是显示问题**，接口与数据库数据正常。用 Python 校验：

```bash
python -c "import requests;print(requests.get('http://127.0.0.1:8010/api/resources/1').json()['name'])"
```

## 九、数据备份与恢复

```bash
# 备份（把 <root密码> 换成 .env 中的 MYSQL_ROOT_PASSWORD；输出文件名自行指定）
docker compose exec -T mysql mysqldump -uroot -p<root密码> \
  --single-transaction --routines --triggers huaihua_logistics > backup.sql

# 恢复
docker compose exec -T mysql mysql -uroot -p<root密码> \
  huaihua_logistics < backup.sql
```

建议：每日定时备份到项目外目录；迁移前先备份一次。

Redis 仅作缓存（键前缀 `hlg:`），丢失不影响业务数据。

## 十、安全清单

上线前逐项确认：

- [ ] `JWT_SECRET` 已改为随机长串（≥32 字符）
- [ ] `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `EMQX_DASH_PASSWORD` 已改
- [ ] `DEVICE_INGEST_TOKEN` 已设置（避免设备上报接口裸奔）
- [ ] `.env` 未进入版本库
- [ ] 生产环境关闭后端直连端口（删除 compose 中 backend 的 `ports`，仅保留 Nginx 入口）
- [ ] 生产环境收紧 `CORS_ORIGINS` 为实际域名（compose 已按 `HHLG_WEB_PORT` 自动生成）
- [ ] 启用 HTTPS（见下）
- [ ] 定期备份 MySQL

### 10.1 启用 HTTPS / WSS

前端 WebSocket 地址会按页面协议自动切换为 `wss://`，只需为 Nginx 增加 TLS：

1. 将证书挂载到容器，例如 `./certs:/etc/nginx/certs:ro`
2. 在 `nginx.conf` 增加 443 server 块并复用现有 `location` 配置
3. 增加 80 → 443 跳转
4. 将 443 端口加入 frontend 的 `ports`

## 十三、自动化测试与 CI

后端提供基于 pytest 的接口级回归测试（认证、修改密码与刷新令牌、登录失败限流、审计日志、资源审核、订单与佣金、撮合、评价与信用分、IoT 告警与阈值规则、设备权限与离线检测、分页、运营统计）。
前端使用 Vitest 覆盖错误文案提取与 Pinia store 的实时事件处理。

```bash
# 后端
cd backend
pip install -r requirements-dev.txt
python -m pytest tests -q

# 前端（单元测试 + 类型检查 + 构建）
cd frontend-vue
npm install
npm run test
npm run build
```

说明：

- 测试使用独立库 `hhlg_test`（不存在会自动创建），不会污染开发库
- 测试用例运行前会把 `REDIS_URL` 指向不可达端口，缓存自动降级为 miss，因此不依赖 Redis
- `TestClient` 不进入 lifespan，不会启动 MQTT 订阅线程与后台协程
- 如需改库地址：`TEST_DATABASE_URL=mysql+pymysql://user:pass@host:port/hhlg_test`
- CI 配置见 `.github/workflows/ci.yml`：push / PR 时自动跑后端测试与前端测试、类型检查、构建
